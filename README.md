# 千盈传送

> 打开浏览器就能传文件，对方无需安装任何客户端

## 介绍

同事催着要大文件？微信传不了？U 盘找不到？发个链接过去，对方浏览器打开就能收，省心省力。WebRTC P2P 直连传输，文件不经过服务器，内网带宽充分利用。跨平台支持 iOS / Android / Windows / macOS。

## 核心特性

- **零安装**：纯浏览器使用，无需任何客户端
- **P2P 直传**：WebRTC 点对点传输，充分利用内网带宽
- **跨平台**：iOS、Android、Windows、macOS 全支持
- **相册保存**：图片和视频可保存到手机相册（需开启 HTTPS 反代）
- **内置反代**：自带反向代理，搭配飞牛 DDNS 域名即可从外网访问
- **自动证书**：自动复用飞牛 NAS 系统证书，开箱即用
- **主题适配**：跟随飞牛系统自动切换明暗模式
- **双架构**：x86 与 ARM 双架构支持

## 安装说明

### 1. 通过飞牛应用中心安装

将 `fn_qycs.fpk` 上传到飞牛 NAS，在应用中心手动安装。

### 2. 安装配置

安装时设置服务监听端口（默认 `5553`），安装完成后飞牛会自动启动服务。

## 使用说明

### 局域网传输

1. 同一局域网内，发送方和接收方都打开浏览器访问 `http://NAS_IP:5553`
2. 发送方拖入文件或点击选择
3. 选择右侧在线设备作为接收目标
4. 点击发送，接收方确认即可

### 公网访问（可选）

如果需要从外网访问，或让手机端保存图片/视频到相册：

1. 打开应用桌面图标，进入「公网访问配置」
2. 配置 HTTPS 端口（默认 `7753`）
3. 选择飞牛已签发的域名证书
4. 确保路由器已配置 HTTPS 端口的端口转发

> **重要提示**：iPhone / Android 在非 HTTPS 环境下，浏览器会禁止网页将图片、视频保存到相册。只有开启 HTTPS 反向代理后才能保存。

> **跨网传输（暗号房间）说明**：跨网络互传依赖 WebRTC 穿透。本应用设计上**默认不走 TURN 中继**，仅启用公共 STUN 服务器。
> - 若收发双方均处于**对称型 NAT** 或严格防火墙环境，**仅靠 STUN 无法穿透，跨网互传不被支持**（前端会明确提示「不支持 TURN 中继互传」并阻止发起）。
> - 如需在对称型 NAT 下跨网互传，必须配置 TURN 中继：设置环境变量 `TURN_URLS`（逗号分隔，如 `turn:your-turn-server:3478`），可选 `TURN_USERNAME` / `TURN_CREDENTIAL` 提供凭据。
> - 应用会在房间内对双方网络能力做**真实校验**，只有在确实具备公网直连或 TURN 中继时才允许跨网传输；否则请双方改为同一局域网或连接同一热点/WiFi 后直接互传。

## 技术原理

```
发送端 ──WebSocket 信令── 服务器 ──WebSocket 信令── 接收端
   │                                                     │
   └────────────── WebRTC DataChannel ────────────────────┘
                     文件数据直传
```

- WebSocket 用于设备发现和信令交换
- 文件数据通过 WebRTC DataChannel 点对点直传
- 服务器不参与文件传输，不占用 NAS 带宽

## 常见问题

**Q: 为什么接收方看不到发送方？**
A: 确保双方都在同一局域网，且都通过浏览器打开了同一个地址。防火墙或网络隔离可能会影响设备发现。

**Q: 图片/视频无法保存到手机相册？**
A: 手机浏览器需要 HTTPS 环境才能写入相册。请在「公网访问配置」中开启 HTTPS 反向代理。

**Q: 传输速度慢？**
A: P2P 直传速度取决于局域网络状况。Wi-Fi 下通常可跑满内网带宽，千兆有线可达 900 Mbps+。

**Q: 跨网互传（暗号房间）提示「不支持 TURN 中继互传」无法发送？**
A: 这是设计预期行为。本应用默认不走 TURN 中继，若收发双方均处于对称型 NAT / 严格防火墙，仅靠 STUN 无法穿透，跨网互传不被支持（前端会阻止发起并提示）。两种解决方式：
- 在应用环境变量配置 `TURN_URLS`（及 `TURN_USERNAME` / `TURN_CREDENTIAL`）启用 TURN 中继；
- 或将双方改为同一局域网 / 同一热点后直连传输。

## 更新日志

### v2.0.1

- **网络隔离逻辑重构**：设备发现判定标准从「IP 是否为私网」改为「与谁同子网」
  - 与服务器同子网（含服务器自身热点）→ 局域网，自动互见、WebRTC 直连（速度快）
  - 与另一客户端连同一热点/WiFi（前端探测局域网 IP 同 /24 前缀）→ 同用户子网，自动互见、直连
  - 其余（移动网络、异网、跨子网）→ 公网受限，仅可通过暗号房间互传（备选方案）
- **修复公网模式重复提示 Bug**：公网受限用户收到 `lan_only` 后强制切换至房间 Tab，不再停留在局域网 Tab 显示重复空态文案；状态栏区分「局域网模式 / 公网模式」
- **设备上线/下线事件按同子网过滤**：`BroadcastLan` 仅通知与源设备同子网的设备，异网/异热点设备不再互相感知
- **设备昵称公平随机**：固定名（袁粑粑等）与词缀×水果组合名融合进同一 Fisher-Yates 洗牌池，各昵称出现频率一致、无顺序偏好；离线释放后重新放回待取池，避免昵称池随时间缩小
